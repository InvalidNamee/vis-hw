Web layout answers three questions: How much space does an element occupy? How are multiple elements arranged? How is space redistributed when a container becomes narrower? Instead of using unrelated examples, the following six steps build one visualization course project gallery.

<div className="prose">

> **Case brief: a gallery for visualization course projects**
>
> We are creating a gallery for a visualization course. Students move between sections in the header, filter by topic and year in the sidebar, browse projects such as Urban Heat, Commuting Flows, and Air Quality in the main region, and find course notes and data sources in the footer. The page can stand alone or be embedded in a narrow course platform, so it must rearrange itself as its container changes.

</div>

The six steps develop the same page in sequence: create a predictably sized project card, preserve its content flow while positioning a badge, build the page with Grid, arrange the project toolbar with Flexbox, add container queries, and verify the result. The first five steps use independent “Explanation / Key code / Demo” tabs; the sixth connects all the results.

## Step 1: define the project card box model

Begin with the case’s smallest repeated unit: a project card. Separating content, padding, border, and card spacing prevents the later three-column layout from overflowing because of incorrect size calculations.

<HomeworkTabs>
<TabsContent keepMounted value="explanation">
<div className="prose">

### Allocate space to the first project card

A project card has four layers from inside out: `content` holds the title and summary, `padding` creates breathing room inside the boundary, `border` marks the visible edge, and `margin` separates the card from external elements.

The default `content-box` adds padding and borders outside the declared width. With `border-box`, they are included. This case applies `box-sizing: border-box` so the card width in CSS matches the visible width.

Use `padding` inside each card and let the Grid’s `gap` control consistent space between cards. Project titles may be long, so Grid items must also be allowed to shrink instead of forcing the page wider.

### Decision order for this step

1. Set the project card’s visible width and use `border-box`.
2. Use `padding` inside cards and `gap` between cards.
3. Use `min-width: 0` where long titles must be able to shrink.

</div>
</TabsContent>

<TabsContent keepMounted value="code">
<div className="prose">

### Write a predictably sized project card

```html locale="en-US" title="project-card.html"
<article class="project-card">
  <h2>Urban Heat Island Map</h2>
  <p>Compare temperature and green-space coverage.</p>
</article>
```

```css locale="en-US" title="project-card.css"
*, *::before, *::after {
  box-sizing: border-box;
}

.project-card {
  width: 320px;
  padding: 20px;
  border: 2px solid #93c5fd;
}
```

The card’s visible width is `320px`; the content area automatically subtracts horizontal padding and borders. With the default `content-box`, the visible width becomes `364px` (`320 + 40 + 4`), making the future three-column layout more likely to exceed its intended width.

</div>
</TabsContent>

## Step 2: keep card content in normal flow

With predictable dimensions in place, add the project title, summary, and link. They should take space in sequence and determine the card’s height; only the “NEW” badge needs to overlay the top-right corner.

<HomeworkTabs>
<TabsContent keepMounted value="explanation">
<div className="prose">

### Let the main content flow naturally

In normal flow, block boxes follow the block axis and inline content wraps when space runs out. The case card uses `position: relative` to establish a positioning context without losing its place. Its badge uses `position: absolute` and leaves normal flow.

The title, summary, and “View project” link remain unpositioned, so they still determine the card’s height. Absolute positioning suits this local overlay; it is not a sound foundation for the entire header, sidebar, or project region.

As summaries grow, cards should grow naturally. Give only genuine scrolling regions explicit size constraints and `overflow: auto`. Do not hide errors with `overflow: hidden`, which can clip text and keyboard focus.

### Positioning rule for this step

Keep structural content in normal flow and position only status information that needs no reserved space. Then check that the badge does not cover the heading and that keyboard focus remains visible.

</div>
</TabsContent>

<TabsContent keepMounted value="code">
<div className="prose">

### Take only the project badge out of normal flow

```html locale="en-US" title="positioned-project-card.html"
<article class="project-card">
  <span class="project-card__badge">NEW</span>
  <h2>Urban Heat Island Map</h2>
  <p>Compare temperature and green-space coverage.</p>
  <a href="#urban-heat">View project</a>
</article>
```

```css locale="en-US" title="positioned-project-card.css"
.project-card {
  position: relative;
  padding: 24px;
}

.project-card__badge {
  position: absolute;
  inset-block-start: 12px;
  inset-inline-end: 12px;
}
```

The parent stays in normal flow; only the badge leaves it. The title, summary, and link take space in sequence and naturally make the project card taller when its summary grows.

## Step 3: build the project gallery with Grid

Now place the stable card inside the complete page. The case needs a header, filter sidebar, project region, and footer, while the project region itself contains three cards. This two-dimensional relationship is a good fit for Grid.

<HomeworkTabs>
<TabsContent keepMounted value="explanation">
<div className="prose">

### Describe the case regions as tracks

The outer Grid uses `160px minmax(0, 1fr)`: the filter sidebar has a fixed `160px` track and the project region fills the rest. The `0` in `minmax(0, 1fr)` lets the main track shrink so long project titles do not force the whole page wider.

Because the case regions have clear roles, `grid-template-areas` names `header`, `sidebar`, `main`, and `footer`. A nested Grid in the project region uses `repeat(3, minmax(0, 1fr))` for the three cards.

Grid distributes space; it does not replace HTML semantics. Keep `header`, `aside`, `main`, and `footer` in the document and use CSS to control their visual arrangement.

</div>
</TabsContent>

<TabsContent keepMounted value="code">
<div className="prose">

### Combine the header, filters, and project region

```html locale="en-US" title="project-gallery.html"
<div class="project-gallery">
  <header class="gallery-header">Visualization Project Gallery · Course navigation</header>
  <aside class="gallery-sidebar">Filter projects by topic and year</aside>
  <main class="gallery-main">
    <div class="project-grid">
      <article>Urban Heat</article>
      <article>Commuting Flows</article>
      <article>Air Quality</article>
    </div>
  </main>
  <footer class="gallery-footer">Course notes and data sources</footer>
</div>
```

```css locale="en-US" title="project-gallery.css"
.project-gallery {
  display: grid;
  grid-template-columns: 160px minmax(0, 1fr);
  grid-template-areas:
    "header header"
    "sidebar main"
    "footer footer";
  gap: 16px;
}

.gallery-header { grid-area: header; }
.gallery-sidebar { grid-area: sidebar; }
.gallery-main { grid-area: main; min-width: 0; }
.gallery-footer { grid-area: footer; }

.project-grid {
  display: grid;
  grid-template-columns: repeat(3, minmax(0, 1fr));
  gap: 16px;
}
```

</div>
</TabsContent>

## Step 4: arrange the project toolbar with Flexbox

With the page structure in place, add an overview toolbar above the cards. Its left side shows “Course projects / 12 projects,” and its right side summarizes map, chart, and story projects. These items follow one primary axis, making Flexbox appropriate.

<HomeworkTabs>
<TabsContent keepMounted value="explanation">
<div className="prose">

### Distribute the toolbar’s remaining space

`display: flex` arranges items horizontally by default. `justify-content: space-between` places the title and type summary at opposite ends, while `align-items: center` aligns them vertically.

The title group uses `flex: 1 1 220px` and `min-width: 0`, so it can fill remaining space and still shrink. The type summary keeps its intrinsic width. With `flex-wrap: wrap`, the summary moves below the title in a narrow embed instead of being clipped.

This step also demonstrates nesting: Grid manages the page regions, while Flexbox manages one row inside the project region.

</div>
</TabsContent>

<TabsContent keepMounted value="code">
<div className="prose">

### Put the project heading and type summary on one row

```html locale="en-US" title="project-toolbar.html"
<div class="project-toolbar">
  <div class="project-toolbar__title">
    <strong>Course projects</strong>
    <span>12 projects</span>
  </div>
  <div class="project-toolbar__summary" aria-label="Project type summary">
    <span>Maps · 4</span>
    <span>Charts · 5</span>
    <span>Stories · 3</span>
  </div>
</div>
```


## Step 5: adapt the gallery to its container

The wide layout is complete, but the gallery must also work inside the course platform. In a narrow container, filters should move above the project list and three card columns should become one. Simply shrinking everything does not solve those spatial relationships.

<HomeworkTabs>
<TabsContent keepMounted value="explanation">
<div className="prose">

### Rearrange the case based on its own width

Declare `container-type: inline-size` on the gallery embed, then query its inline size with `@container`. The same gallery can now respond to the width it actually receives in either a full page or a narrow course-platform region.

Container queries suit this reusable region. `@media` still suits viewport-level changes such as site navigation and page margins. A breakpoint should answer a concrete problem: Is the sidebar squeezing the project region? Can three cards still sit comfortably side by side?

The case uses `560px` as its rearrangement point. Below it, the outer layout and project-card Grid both become a single column. No project content is removed, and the sidebar width setting temporarily has no effect.

</div>
</TabsContent>

<TabsContent keepMounted value="code">
<div className="prose">

### Declare a container breakpoint for the gallery

```css locale="en-US" title="responsive-project-gallery.css"
.gallery-embed {
  container-type: inline-size;
}

.gallery-layout {
  display: grid;
  grid-template-columns: 160px minmax(0, 1fr);
  gap: 16px;
}

.project-grid {
  display: grid;
  grid-template-columns: repeat(3, minmax(0, 1fr));
  gap: 16px;
}

@container (max-width: 560px) {
  .gallery-layout,
  .project-grid {
    grid-template-columns: 1fr;
  }
}
```

“Narrow container” constrains the case preview to `360px`, below the `560px` breakpoint. You can therefore see the rearrangement without resizing the browser window.

</div>
</TabsContent>

## Step 6: verify the complete case

The first five steps have progressed from one project card to a complete responsive gallery. Replace “looks about right” with checks that prove each step supports the same case.

<div className="prose">

### Follow the case through verification

1. **Inspect project cards:** confirm that `border-box` makes their widths predictable and that internal `padding` and inter-card `gap` have distinct roles.
2. **Inspect card content:** add a longer project title and summary. Confirm that content increases the card height and only the badge leaves normal flow.
3. **Inspect page structure:** confirm that the header, filter sidebar, project region, and footer keep semantic elements while Grid controls their visual arrangement.
4. **Inspect the project toolbar:** switch between wide and narrow containers. Confirm that the heading and type summary wrap without clipping.
5. **Inspect the embedded state:** select the narrow container, confirm that filters sit above a single-column project list, then use the Tab key to check visible focus.

### Keep the case’s adjustable parameters together

```css locale="en-US" title="project-gallery-tokens.css"
.project-gallery {
  --content-max: 72rem;
  --region-gap: 16px;
  --region-padding: 16px;
  --sidebar: 160px;
  width: min(100%, var(--content-max));
  margin-inline: auto;
  padding-inline: var(--region-padding);
  container-type: inline-size;
}

.project-gallery__body {
  display: grid;
  grid-template-columns: var(--sidebar) minmax(0, 1fr);
  gap: var(--region-gap);
}

@container (max-width: 560px) {
  .project-gallery__body {
    grid-template-columns: 1fr;
  }
}
```

These properties correspond to the controls in Step 5. When a problem appears, you can identify whether the filter sidebar, region gap, region padding, or container breakpoint caused it.

### Case completion criteria

- In a wide container, the filter sidebar has a fixed width, the project region fills the remaining space, and three cards sit side by side.
- Grid manages the two-dimensional page regions, Flexbox arranges the one-dimensional toolbar, and `gap` expresses space between siblings.
- Long project titles and summaries do not break out of their cards or create unnecessary horizontal scrolling.
- In a narrow container, filters and projects stack, cards use one column, and all content remains visible, readable, and operable.
