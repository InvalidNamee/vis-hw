Web layout answers three questions: How much space does an element occupy? How are multiple elements arranged? How is space redistributed when a container becomes narrower? This chapter follows the sequence “calculate sizes → understand flow → define regions → align content → adapt the layout → verify” to turn these questions into CSS rules you can inspect and change.

Each layout concept has its own “Explanation / Key code / Demo” tabs. Read the explanation, compare it with the code, then adjust parameters or inspect the structure in the demo. The final verification section is presented as continuous text so you can work through it from start to finish.

## Start with the box model: calculate the space

The box is the smallest unit of layout. Distinguishing content, padding, border, and margin makes width calculations predictable instead of a matter of guesswork.

<HomeworkTabs>
<TabsContent keepMounted value="explanation">
<div className="prose">

### Inner and outer space

A block-level element has four layers, from inside out: `content` holds text or child elements, `padding` is the inner space between content and border, `border` is the visible boundary, and `margin` is the outer distance between this box and other boxes.

The most common source of confusion is `width`. With the default `content-box`, padding and borders are added to the declared width. With `border-box`, they are included in it. Projects commonly set `box-sizing: border-box` globally so the declared width matches the visible width more closely.

Both `padding` and `margin` create space, but they serve different purposes: padding separates content from its boundary, while margin separates boxes. For consistent spacing between Grid or Flex items, prefer `gap` over individual margins.

### A reusable decision process

1. Decide how wide the element’s **visible box** should be, then choose `border-box` or calculate the content width separately.
2. Determine whether the space belongs inside the box (`padding`) or outside it (`margin` / `gap`).
3. If content may be long, use `min-width: 0` on Grid items so their minimum content size does not force the parent to overflow horizontally.

</div>
</TabsContent>

### Build a box with predictable dimensions

```html locale="en-US" title="box-model.html"
<article class="card">
  <h2>A predictable card</h2>
  <p>Content, padding, and borders make up the visible box.</p>
</article>
```

```css locale="en-US" title="box-model.css"
*, *::before, *::after {
  box-sizing: border-box;
}

.card {
  width: 320px;
  padding: 20px;
  border: 2px solid #93c5fd;
  margin: 24px;
}
```

In this example, the card’s visible width is `320px`. The content area automatically subtracts the left and right padding and borders. Margin sits outside the visible box and only occupies external space. Removing `box-sizing: border-box` restores `content-box`, making the visible width `364px` (`320 + 40 + 4`).

## Understand normal flow before choosing positioning

Even without Grid, Flexbox, or positioning rules, the browser arranges content in normal document flow. Building a readable structure with that default flow before choosing another layout mode is usually more robust than fixing elements to coordinates from the start.

<HomeworkTabs>
<TabsContent keepMounted value="explanation">
<div className="prose">

### The default layout already has an order

In normal flow, block boxes follow one another along the block axis and usually fill the container’s available inline width. Inline boxes flow with text on the same line and wrap when space runs out. `display: grid` and `display: flex` establish new layout modes inside a container, while the container itself remains in the surrounding document flow.

`position: relative` preserves the element’s original space and often establishes the containing block for absolutely positioned children. `position: absolute` and `fixed` remove elements from normal flow, so surrounding content no longer reserves room for them. Absolute positioning therefore suits badges, floating panels, and local overlays; it is a poor foundation for body content and sidebars.

`position: sticky` suits tables of contents and toolbars: an element moves with the document until it reaches a specified threshold, then stays within its container’s bounds. With any positioning method, check overlaps, scrolling containers, and whether keyboard focus remains visible.

### Let content determine height

Avoid fixed heights for body content where possible. A box naturally grows as its text gets longer. If a scrolling region is necessary, use explicit size constraints and `overflow: auto`. Do not hide layout errors with `overflow: hidden`, which can clip both text and focusable controls.

</div>
</TabsContent>

<TabsContent keepMounted value="code">
<div className="prose">

### Take only the badge out of normal flow

```html locale="en-US" title="positioned-card.html"
<article class="card">
  <span class="card-badge">NEW</span>
  <h2>Course announcement</h2>
  <p>The body stays in normal flow and determines the card’s height.</p>
</article>
```

```css locale="en-US" title="positioned-card.css"
.card {
  position: relative;
  padding: 24px;
}

.card-badge {
  position: absolute;
  inset-block-start: 12px;
  inset-inline-end: 12px;
}

.scroll-region {
  max-width: 100%;
  overflow-x: auto;
}
```

The parent’s `position: relative` establishes the positioning context while preserving its place in normal flow. Only the badge leaves the flow; the heading and body still expand the card naturally.

## Build the page structure with Grid

When a layout involves both rows and columns, CSS Grid places page regions on a shared two-dimensional grid. Define the page structure first, then nest smaller grids inside the main content to keep the hierarchy clearer than a stack of margin adjustments.

<HomeworkTabs>
<TabsContent keepMounted value="explanation">
<div className="prose">

### Describe space as tracks

A Grid container consists of rows, columns, and gutters (gaps). `grid-template-columns: 160px minmax(0, 1fr)` gives the sidebar a fixed `160px` track and lets the main content fill the remaining space. The `0` in `minmax(0, 1fr)` explicitly allows the main column to shrink, a useful way to prevent overflow from long headings, code blocks, and tables.

Use `grid-template-areas` when page regions have clear roles: `header`, `sidebar`, `main`, and `footer` express the layout directly. For repeated cards, `repeat()` and `minmax()` are often a better way to describe repeated columns.

Grid distributes space between regions; it does not replace HTML semantics. Keep structural elements such as `header`, `aside`, `main`, and `footer`, and use CSS Grid to control their visual positions.

</div>
</TabsContent>

<TabsContent keepMounted value="code">
<div className="prose">

### Build a structure with named areas

```html locale="en-US" title="page.html"
<div class="page">
  <header class="page-header">Site title and navigation</header>
  <aside class="page-sidebar">Filters and notes</aside>
  <main class="page-main">
    <div class="cards">
      <article>Content A</article>
      <article>Content B</article>
      <article>Content C</article>
    </div>
  </main>
  <footer class="page-footer">Additional information</footer>
</div>
```

```css locale="en-US" title="page.css"
.page {
  display: grid;
  grid-template-columns: 160px minmax(0, 1fr);
  grid-template-areas:
    "header header"
    "sidebar main"
    "footer footer";
  gap: 16px;
}

.page-header { grid-area: header; }
.page-sidebar { grid-area: sidebar; }
.page-main { grid-area: main; min-width: 0; }
.page-footer { grid-area: footer; }

.cards {
  display: grid;
  grid-template-columns: repeat(3, minmax(0, 1fr));
  gap: 16px;
}
```

</div>
</TabsContent>

## Use Flexbox for one-dimensional alignment

When elements mainly follow a single axis, Flexbox provides a direct way to align them and distribute remaining space. Navigation, toolbars, button groups, and card headings are common examples.

<HomeworkTabs>
<TabsContent keepMounted value="explanation">
<div className="prose">

### Set the main axis, then align the cross axis

`display: flex` lays out items horizontally by default. `flex-direction` sets the main axis, `justify-content` distributes space along it, and `align-items` controls alignment on the cross axis. Their effects change when the main axis changes direction.

For toolbars with content of varying lengths, a common combination is `align-items: center`, `gap` between items, `justify-content: space-between` for opposite-end alignment, and `flex-wrap: wrap` when there are many buttons. To let a title fill the remaining space while buttons retain their width, give the title `flex: 1` and use `min-width: 0` on items that long text might otherwise stretch.

Grid and Flexbox can be nested: Grid handles the major page regions, and Flexbox handles a row of controls within a region. Choose based on spatial relationships rather than component names.

</div>
</TabsContent>

```html locale="en-US" title="toolbar.html"
<div class="toolbar">

    <strong>Layout lab</strong>
    <span>The title fills the remaining space</span>
  </div>
  <div class="toolbar-actions">
    <button type="button">Fluid width</button>
    <button type="button">Narrow container</button>
  </div>

.toolbar {
  display: flex;
  align-items: center;
  justify-content: space-between;
  flex-wrap: wrap;
  gap: 12px 20px;
}

.toolbar-title {
  display: flex;
  align-items: baseline;
  flex: 1 1 220px;
  min-width: 0;
  gap: 12px;
}

.toolbar-actions {
  display: flex;
  flex: 0 0 auto;
  gap: 8px;
}
```

## Adapt layouts with container queries

Responsive layout changes relationships between regions instead of simply shrinking everything. A sidebar can move above the body, three card columns can become one, and a toolbar can wrap. Container queries let us respond to the component’s own width instead of only the browser viewport.

<HomeworkTabs>
<TabsContent keepMounted value="explanation">
<div className="prose">

### Let a component adapt to its container

Declare `container-type: inline-size` on the parent you want to observe, then query its inline size with `@container`. The same card can then adapt to its actual available width, whether it appears in a wide main area or a narrow sidebar.

Container queries suit reusable components. `@media` still suits viewport-level changes, such as showing navigation or changing page margins. Both can coexist, but breakpoints should address specific space constraints rather than arbitrary device categories.

A useful approach is to begin with a safe layout for narrow spaces, then add columns in wider containers. Every breakpoint should answer an observable question: Can the cards still sit comfortably side by side? Is the sidebar squeezing the body?

</div>
</TabsContent>

<TabsContent keepMounted value="code">
<div className="prose">

### Declare a container and rearrange at a breakpoint

```css locale="en-US" title="responsive-layout.css"
.content-region {
  container-type: inline-size;
}

.content-layout,
.card-list {
  display: grid;
  grid-template-columns: 160px minmax(0, 1fr);
  gap: 16px;
}

.card-list {
  grid-template-columns: repeat(3, minmax(0, 1fr));
}

@container (max-width: 560px) {
  .content-layout,
  .card-list {
    grid-template-columns: 1fr;
  }
}
```

`@container` queries the width of `.content-region`. Selecting “Narrow container” in the demo sets the container to `360px`, below the `560px` breakpoint, triggering the rule without resizing the browser window.

</div>

## Turn layout problems into a verification process

A finished layout is not necessarily a reliable one. Replace “looks about right” with conditions you can check in the browser to uncover overflow, alignment, and responsive layout problems.

<div className="prose">

### A four-step check

1. **Inspect structure:** use developer tools to inspect Grid rows, columns, and areas, along with the Flex main axis. Confirm that the visual hierarchy still reflects the HTML semantics.
2. **Inspect dimensions:** work inward through margin, border, padding, and content, and confirm that width calculations match your `box-sizing` choice.
3. **Test extreme content:** try long headings, long words, button groups, and empty states. Check for horizontal scrolling, overlaps, and controls that cannot be clicked.
4. **Vary the available space:** resize the container and check that each `@container` breakpoint solves a specific problem. Then navigate with the Tab key to confirm that layout changes do not hide focus.

### Keep adjustable parameters together

```css locale="en-US" title="layout-tokens.css"
.layout-sandbox {
  --content-max: 72rem;
  --space: 16px;
  --sidebar: 160px;
  width: min(100%, var(--content-max));
  margin-inline: auto;
  padding-inline: var(--space);
}

.layout-sandbox__body {
  display: grid;
  grid-template-columns: var(--sidebar) minmax(0, 1fr);
  gap: var(--space);
}

@container (max-width: 560px) {
  .layout-sandbox__body {
    grid-template-columns: 1fr;
  }
}
```

Extracting widths and spacing into custom properties lets you change them together from the layout lab or a debugging panel. When something goes wrong, it also makes it easier to identify whether the cause is a track, a gap, or the box model.

### Final checklist

After completing a page, verify at least the following:

- At wide viewport sizes, the main regions have clear boundaries and the main content can shrink.
- Grid handles two-dimensional regions, Flexbox handles one-dimensional alignment, and `gap` expresses spacing between siblings.
- Long content does not break out of its container or cause unnecessary horizontal scrolling.
- Narrow containers rearrange as intended, and all content remains visible, readable, and usable.
