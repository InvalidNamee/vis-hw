# HW03 工具与 UI 冗余检查


> 后续实施：已按用户要求将入口从 69 个合并为 59 个，删除重复按钮、旧工具实现、不可达 UI 分支与废弃工具栏样式；未保留旧操作兼容或迁移。布局与验证结果见 `docs/hw03.md` 的“工具与界面精简”。以下保留修改前的检查记录。

检查日期：2026-10-15。对象为当前工作区源码及本地开发页面 `/hw03/`，包含已有未提交修改。本次只检查并记录，没有修改业务代码。

## 结论

目前有 **8 个分区、27 个工具组、69 个工具入口**。主要冗余来自基础工具与后续扩展工具并列，以及多轮 UI 改版留下的控件、样式和分支。

优先收敛 6 个基础入口，可将入口数从 69 降至 63。简单操作应作为统一工具内的默认配置或快捷模式，避免为同一任务再增加一次工具选择。底层旧操作仍需支持备份、时间线和离线重放。

## 1. 优先合并的工具入口

| 当前入口 | 建议 | 核对结果与兼容要求 |
| --- | --- | --- |
| 随机抽样 `sample` / 分层与加权抽样 `sampling` | 一个“抽样”入口；默认无分层、无权重、不放回 | 对应数量和种子下，代表性数据的行列输出一致；扩展工具另外提供抽样诊断。旧工具要求数量至少为 1，扩展工具允许 0，不能据此宣称全部校验相同。 |
| 重命名字段 `rename` / 批量字段命名 `columnRename` | 一个“字段命名”入口；单字段直接编辑名称 | 批量工具的“逐项指定名称”可完成单字段重命名；代表性行列输出一致。保留简单工具的直接输入体验。 |
| 创建计算列 `calculate` / 组合公式 `formula` | 在公式工具内提供“两字段四则运算”快捷编辑 | 两字段除法在代表性数据中输出一致，包含缺失值及除零；扩展工具已有结果解释。“数值运算与截断”支持批量字段，仍有独立使用价值。 |
| 快速分组汇总 `group` / 多维聚合 `groupMulti` | 一个“分组汇总”入口；默认一个键、一个指标、一个方法 | 明确设置首次出现顺序、包含缺失键后，代表性行列输出一致。默认行为已有差异：旧工具保留首次出现顺序，扩展工具默认排序并排除缺失键。 |
| 快速透视表 `pivot` / 多维透视 `pivotMulti` | 一个“透视表”入口；单行键、单列键、单指标作为默认配置 | 从实现确认功能重叠；本次没有进行这两者的行列相等对照。字段编码、列轴元信息、缺失处理与排序不同，不能直接改写旧操作。 |
| 快速字段关联 `join` / 多键关联 `merge` | 一个“字段关联”入口；默认一对键，进阶参数折叠 | 同名单键、无字段碰撞的代表性左连接输出一致。不同键名时右键是否保留、重名后缀、空值归一化存在差异，旧操作必须继续按原规则重放。 |

证据位置：`controller.ts:129` 的完整工具目录、`controller.ts:266` 起的基础表单、`extended-tools.ts` 的扩展表单，以及 `model.mjs:148` 起的基础操作实现。

第二批可考虑：

- `rank` / `groupRank`：不分组时计算目标重叠，但普通排名支持自定义结果列名；统一前需要补齐这一体验。
- `month` / `resample`：按月汇总适合作为重采样预设，但时区、空时段、周期标签和输出格式需要明确保留。
- `groupMulti` / `groupNamed`：已经共用 `groupingOperation`。可以统一聚合表单，提供“字段 × 方法”和“逐项指定”两种指标配置；逐项命名的能力应保留。

## 2. UI 中重复或无效的控件

### 优先：筛选有重复提交入口

添加条件并完成预览后，“应用操作”和“保留选中”同时出现，均可提交当前正向筛选；旁边还有“排除选中”。

- `controller.ts:93` 生成选择操作按钮，`controller.ts:277` 生成表单提交按钮。
- `controller.ts:548` 提交预览操作；`controller.ts:550` 再次构造并提交相同条件的筛选。
- 建议在筛选编辑器内统一为“应用筛选 / 排除匹配”，把图表临时选择的提交按钮留在图表选择场景。

### 优先：当前方法不使用的参数仍显示

- `dtype` 选择 Int64、Float64、string、boolean 时，仍显示“数据类型” `valueType`；它只在分类集合解析时使用。浏览器已确认 Int64 下可见。
- `category` 的“生成分类编码”仍显示 `valueType`，但该分支在解析分类集合之前已经返回。
- 窗口先选择相关／协方差，再切到 shift 或累计方法时，`visibleControls` 仍返回 `other`。它只依赖残留的 `aggregate`，没有同时约束当前窗口方法。
- 普通筛选的“为空 / 非空”仍显示“值”输入框，而执行条件不读取它。

位置：`extended-tools.ts:8`、`:9`、`:40`、`:69`，`dtypes.mjs:7` 起，`controller.ts:266`。建议把显示条件集中在工具配置中，表单渲染和参数采集使用同一套规则。

“文本清洗”已经在 `controller.ts:213` 按方法隐藏查找、替换、切片和新列名称，浏览器确认默认清除空格只有字段与方法两个输入。这部分没有上述显示问题；但条件写在控制器中，参数采集仍遍历另一套 `visibleControls`，可在整理时统一。

### 次优先：操作层级和辅助信息

- 有 3 个工具组仅含一个工具：重复值 → 删除完全重复的行、相关性分析 → 相关与协方差、多层列标签 → 多层列标签。仍需展开下拉菜单才能进入；可直接打开工具。
- 参数变化已经自动预览（`requestPreview`、`openTool`），所有编辑器仍保留同等显著的“预览变化”按钮。可保留预览状态，把手动操作降为失败时的“重试预览”。
- 多字段表单会在每个选择器后重复显示 Ctrl / ⌘ 多选说明；可以在表单中说明一次。
- 时间线每一步的小字与“详情”都输出同一份 `operationDetail`（`controller.ts:326`）。详情可以补充独有信息，如参数和前后变化，避免仅重复摘要。

## 3. 实现中的冗余与遗留

- **旧工具组样式未清理。** 当前模板生成 `.loom-tool-dropdown` / `.loom-tool-menu`，源码中 `.loom-tool-group` 只剩 `style.css` 使用，共 15 处选择器引用。旧横向工具栏、换行网格和新下拉菜单三轮布局叠加，`.loom-tools` 有 7 处规则块。应删除已无 DOM 的选择器，再整理相互覆盖的声明，保留有效断点。
- **清洗操作存在不可达的旧参数分支。** `formOperation` 在 `controller.ts:446` 已由 `extendedTools` 处理 fill、dropMissing、dedup 并返回；`:461` 的旧单字段分支无法到达。`uiControlMap` 中 clean-type、clean-column、fill-method、fill-value、group-mode、sort-column、sort-direction 也已没有对应表单控件。清理这些 UI 遗留不等于删除模型对旧参数的兼容。
- **工具元信息分散。** 目录、名称、搜索别名、侧栏布局名单、控件定义及有效工具列表分别维护。建议以统一目录保存 section、group、label、aliases、layout 和 controls；执行引擎继续按操作类型分发。
- **扩展后的名称仍沿用旧含义。** `dedup` 已支持指定字段和生成标记，仍叫“删除完全重复的行”；`dropMissing` 已支持删列，仍叫“删除字段缺失的行”。可改成“重复值处理”“删除缺失”，避免用户误以为还需要另一个工具。

## 4. 有相似名称、但应保留的能力

| 能力 | 保留原因 |
| --- | --- |
| `rowSelect` / `indexLoc` | 位置或字段值选取与独立行索引标签选取的语义不同。 |
| `concat` / `indexConcat` | 横向按位置拼接与按索引标签对齐的结果不同。可以共用入口，但必须明确选择对齐方式。 |
| `convert` / `dtype` / `dateparse` | 普通值转换、显式 dtype 元信息、日期格式及时区解析不能互换。例如字符串 true 在普通布尔转换中可接受，在可空布尔转换中会失败。 |
| `text` / `strings` / `extractAll` | 原列清洗、新列拆分／提取、多次匹配索引输出均有独立用途。 |
| `pivotMulti` / `crosstab` | 频数及按行／列占比是交叉表的独立能力。 |
| `windows` / `weightedWindow` / `ewm` | 普通窗口、固定形状权重和指数衰减有不同统计定义。 |
| 结果 JSON / 工作区备份 | 前者导出当前结果，后者保留源数据和操作；用途不同。 |
| 顶部导入 / 数据集内导入 | 同一动作的就近快捷入口，冗余成本低于上述问题，无需优先删除。 |

## 5. 验证范围与建议顺序

已完成源码审查、工具目录计数、6 组代表性操作的行列输出对照，以及部分控件显示规则诊断。6 组对照为 sample/sampling、rename/columnRename、calculate/formula、group/groupMulti、rank/groupRank、join/merge；均得到相同行列，但不证明完整语义等价。同时确认 group 默认输出顺序不同。

浏览器核对了中文桌面 1440×1000、窄屏 390×844、工具分组、搜索、文本清洗、类型转换及临时筛选；读取的控制台无脚本错误。没有提交数据操作，没有进行完整工具回归、英文或深色模式验收。本次未修改业务代码，因此未重跑构建和全量测试。

本地证据位于 `output/playwright/`（该目录被 Git 忽略）：

- `hw03-redundancy-probes.json`：对照输入、参数和结果。
- `hw03-redundancy-dtype-parameters.png`：Int64 下无效的“数据类型”参数。
- `hw03-redundancy-filter-actions.yml`：筛选预览中的重复提交入口。
- `hw03-redundancy-desktop.png`、`hw03-redundancy-dtype-mobile.png`：桌面与窄屏检查截图。

建议顺序：先处理无效参数和重复提交按钮，再移除无 DOM 样式及不可达 UI 分支，最后收敛工具入口。入口收敛时保留旧操作类型，并针对备份恢复、历史重放、默认顺序、输出名称和类型元信息做定向回归。
