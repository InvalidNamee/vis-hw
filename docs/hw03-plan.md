# HW03 方案：可视化数据工作台

日期：2026-10-09。本文为实施方案，尚未实现或验证其中功能。

## 1. 产品定位

暂定名称：Data Loom · 数据织坊。

用图形和直接操作完成“加载 → 理解 → 清洗 → 转换 → 分析 → 导出”的完整过程。用户无需编程，也可以理解每一步对数据的影响；熟悉 pandas 的用户可以查看对应代码。

核心设计原则：**图表既呈现结果，也作为操作数据的入口。** 框选散点、拖动直方图区间、点击分类条形，都能生成可编辑的筛选条件；清洗和转换都有前后对比；所有结果能追溯到原始数据和操作步骤。

以 pandas 的常用 DataFrame 工作流作为功能体系，明确支持范围。完整性体现为分析流程闭环、关键操作语义可靠、多表与时间序列可用，不宣称复刻 pandas 的全部 API。

## 2. 页面与视觉设计

直接接入现有作业网站：中文 `/hw03/`，英文 `/en/hw03/`。复用公共导航、语言切换、明暗主题及首页作业卡片。

桌面工作台布局：

```text
┌─────────────────────────────────────────────────────────────┐
│ 数据织坊    当前数据集 · 行列数    导入    导出    中文/EN    │
├────────────┬─────────────────────────────────┬──────────────┤
│ 数据集列表 │ 概览 / 数据 / 清洗 / 分析 / 关联 │ 当前操作设置 │
│ 字段与类型 ├─────────────────────────────────┤ 参数与预览   │
│ 字段分布   │ 主分析区：图表、矩阵或数据表    │ 应用操作     │
│ 操作入口   │ 图表和表格联动，按任务组织内容  │ 结果说明     │
├────────────┴─────────────────────────────────┴──────────────┤
│ 操作时间线：导入 → 清洗 → 筛选 → 分组 → 导出    撤销 / 重做 │
└─────────────────────────────────────────────────────────────┘
```

不把全部图表和工具一次铺满页面。初始只展示数据概览、重点质量问题和推荐的分析入口，选择任务后再展开参数。右侧设置区按需出现。

视觉沿用站点冷灰蓝基调：低饱和背景、清晰的文字层级、细边框、充足留白。蓝色表达选中，橙色表达质量问题；类别使用稳定配色，正负数使用以零为中心的发散色。减少装饰动画，让视觉注意力集中在分布、变化和关系上。

数据表使用固定表头、数字右对齐、等宽数字、类型标识及明确的缺失值显示。提供键盘操作、非颜色提示和图表数值替代视图。窄屏切换为单列主区，字段和设置收进抽屉；复杂多图分析以桌面体验为主。

## 3. 数据加载和默认数据

必做：拖拽或选择 CSV、TSV、JSON 文件，支持多个数据集；CSV 可选择分隔符、表头和编码；JSON 支持对象数组，并对嵌套结构明确提示。

补充：粘贴表格文本；导入 XLSX，选择工作表；通过 URL 读取数据，并在跨域受限时给出本地文件替代路径。自由加载以本地导入为可靠入口，URL 不承诺读取任意网站。

导入后先预览列名、类型和样本，允许修正类型、重复列名与日期解析规则。失败时说明具体位置和原因，避免静默丢弃坏行。

默认使用有固定生成种子的**合成零售订单数据**：订单、商品、地区三张表，覆盖时间、分类、数值、关联键。字段包括订单日期、地区、品类、销售额、成本、数量、折扣等；有意加入少量缺失、重复和异常记录，用来展示清洗价值。明确标注教学合成数据，不作为真实商业结论。

默认数据应能自然回答：销售额如何变化？哪个地区利润较高？折扣和利润有什么关系？异常订单在哪里？关联商品信息后，各品类表现如何？另附干净的小数据样例，用于验证结果。

## 4. 功能矩阵

| 能力 | 对应 pandas 工作流 | 可视化操作和结果 |
| --- | --- | --- |
| 数据理解 | `head`、`info`、`describe`、`value_counts` | 行列数、字段类型、分布小图、分类频数、数值摘要 |
| 选择与筛选 | `loc`、`query`、`sort_values` | 条件构建器、区间拖动、类别点击、散点框选、排序 |
| 缺失值处理 | `isna`、`dropna`、`fillna` | 缺失矩阵、字段缺失率、删除或填充的前后对比 |
| 去重和类型 | `duplicated`、`drop_duplicates`、`astype` | 重复记录预览、去重键选择、类型转换失败定位 |
| 字段转换 | `assign`、字符串操作、日期操作、`cut` | 计算列、拆分与替换、提取年月、分箱后的分布 |
| 分组统计 | `groupby`、`agg`、`transform` | 拖入分组字段和指标，条形图与统计表同步变化 |
| 表格重塑 | `pivot_table`、`melt` | 行列拖拽、热力矩阵、宽表与长表结构示意 |
| 多表关联 | `merge`、`concat` | 选择左右表和关联键，匹配覆盖率与未匹配记录 |
| 时间序列 | `resample`、`rolling`、`shift` | 时间粒度切换、趋势和移动平均、环比变化 |
| 关系与异常 | `corr`、分位数、IQR 方法 | 相关热图、散点、箱线图和异常记录定位 |
| 导出与复现 | `to_csv`、操作链 | 导出结果、图表、工作流和对应 pandas 脚本 |

聚合至少覆盖计数、非空计数、求和、均值、中位数、最小值、最大值、标准差和唯一值数。筛选支持 AND/OR、空值条件、数值范围、文本包含和日期范围。

计算列采用字段与运算符构建器，提供四则运算、条件表达式及常用文本/日期函数。不能使用任意 JavaScript `eval` 执行用户表达式。

## 5. 五个重点亮点

### 5.1 联动探索：从“看图”到“用图筛选”

同一分析视图呈现分布、类别和关系图。点击地区条形，其他图表和数据表同步更新；拖动销售额区间，再框选散点中的异常群体，形成可见的筛选标签。每个标签可以编辑和删除，提供一键清除。

明确区分“临时选择”和“应用到数据”：临时选择用于探索，点击“应用筛选”才写入操作时间线。显示全量与选中样本数，保留灰色背景分布，避免用户失去参照。

### 5.2 数据体检：看见清洗的影响

缺失矩阵显示问题出现在哪些行和列；分布图标出异常范围。选择填充或删除策略后，预览行数、缺失率和分布变化，再应用。异常识别只标记候选记录，由用户决定是否处理。

### 5.3 分组与透视：拖拽构建分析

把“地区”放到分组槽，把“销售额”放到指标槽并选择求和，即生成统计表和条形图；再加入“品类”，切换为分组图或热力矩阵。拖拽之外提供点击选择，保证键盘和窄屏可用。

### 5.4 可视化关联：解释多表合并

用集合示意表达 inner、left、right、outer 的保留范围，同时显示匹配率、未匹配键、预计输出行数和关联键的重复情况。若存在多对多关系，应用前展示实际展开预览，让用户理解为什么行数增加。

### 5.5 操作时间线：可解释、可撤销、可复现

每一步显示参数、输入输出行列数及简短结果。支持撤销、重做、返回任一步，修改历史步骤后重新计算下游；引用字段失效时提示具体步骤。

提供对应 pandas 代码预览和导出，连接图形交互与课程知识。导出的脚本包含读取数据、类型设定、操作顺序和结果保存；仅对已支持且语义已验证的操作生成代码。

## 6. 中英双语一致性

两种语言共用工作台、数据、计算逻辑和操作状态，所有界面文案从统一键值字典读取。翻译范围包括按钮、字段类型、图表标题、图例、工具提示、空状态、错误提示、操作说明及导出报告。

切换语言后保留数据集、图表选择、筛选、步骤、主题和滚动位置。用户导入的列名与分类值保持原样；默认数据使用稳定的内部字段键，以双语显示名称呈现。切换语言不能更改原始数据或分析结果。

数值与日期展示可以本地化，内部数值、日期语义和导出结果保持一致。自动检查字典键对应，并使用同一数据和操作验证两种语言的结果一致。

## 7. 技术实施路径

沿用现有 Astro + TypeScript + D3，在 `src/homework/hw03/` 隔离页面组件、数据模型、操作引擎、图表和文案；入口分别放在中文与英文路由。默认数据放在 `public/data/hw03/`，交付材料放在 `submission/hw03/`。

第一阶段验证浏览器内分析引擎：优先评估 Web Worker 中运行 pandas/Pyodide，以真实 pandas 语义支持常用操作并生成一致代码。先验证加载体积、首次可用时间、文件处理、内存和部署兼容性，再确定是否采用。

若该路径的体验不满足要求，采用 TypeScript 数据引擎与统一操作协议实现已列出的范围，并为关键语义建立 pandas 对照样例。界面与图表始终依赖统一操作协议，避免计算方案变化牵动整体重写。此处是待验证的技术决策，不预设性能结论。

计算与界面分离：数据和类型模式 → 操作描述 → Worker 执行 → 结果与统计 → 图表/表格。用步骤参数和缓存管理历史，避免每一步复制整张表。表格虚拟滚动；散点较多时评估 Canvas；图形可以抽样，但统计默认基于全量，并明确标注显示采样情况。

大文件导入先显示大小及处理进度，允许取消。实际性能上限通过测试确定，并写入说明，不宣称无限数据规模。原始文件默认在浏览器处理；保存工作区需明确包含哪些本地数据。

## 8. 实施顺序与验收

1. **技术验证与设计定稿**：引擎小样、双语状态切换、核心布局、合成数据和计算对照样例。
2. **完成主流程**：导入、概览、筛选、排序、清洗、分组、导出；先跑通一条完整分析链。
3. **完善图形操作**：联动筛选、清洗对比、透视、多表关联、时间序列、计算列、撤销重做和代码导出。
4. **打磨与交付**：明暗主题、双语核对、键盘和窄屏体验、性能测试、发布材料与演示录制。

验收以实际任务为准：

- 首次打开即可操作默认数据；自己的文件可以替换默认数据并完成分析。
- 完成“导入订单 → 处理缺失 → 按图筛选 → 关联商品 → 按地区/月份聚合 → 导出”。
- 多条件筛选、聚合、空值、去重、关联、日期和透视结果与小型对照样例一致。
- 处理零匹配、全空列、重复关联键、转换失败、除零和无有效日期等边界。
- 联动图表与数据表的选中记录一致；撤销/重做准确恢复结果。
- 切换中英和明暗主题不丢失工作区；英文没有遗漏中文提示。
- 导出 pandas 脚本在支持的操作范围内复现结果；未支持项有明确说明。
- 记录实际完成的检查：现有项目 check/build、相关自动化测试及浏览器场景验证。
