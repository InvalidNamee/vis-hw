## 1. 作业目标与叙事

教师要求：用多种可视化表达人工智能作为新质生产力的作用和意义；数据自行查找；表达效果优先，同时考虑网站复杂程度、布局和美观。

核心问题：AI 如何改变生产要素和生产流程，进而提升效率、质量和创新能力？这些收益在什么条件下才能发生？

叙事顺序：理解机制 → 观察发展 → 探索产业 → 检查效率证据 → 动手实验 → 理解转型条件。

新质生产力的概念锚点包括劳动者、劳动资料、劳动对象及其组合的变化，以及高科技、高效能、高质量。投资额、模型数量、采用率用于说明发展条件，不能直接作为全要素生产率提升的证据。

## 3. 两个重点交互

### 产业图谱：从行业进入具体改变

优先覆盖制造、农业、医疗、科研、服务五类场景。每个场景展示“原流程 → AI 介入的任务 → 变化机制 → 有来源的结果 → 适用边界”。

主视图使用 D3 力导向网络连接产业、AI 能力与任务节点，支持拖拽、缩放和点击聚焦；选中节点时突出邻接路径，其余节点淡出，侧面展示流程图、案例说明和证据卡。提供矩阵视图和按钮列表，方便精确比较、键盘操作及窄屏使用。

网络与矩阵先使用有来源的应用分类，不编造行业成熟度或赋能分数。节点间距离是布局结果，不代表产业相似度；无定量权重时使用一致的节点尺寸和线宽。没有可比较定量数据的场景采用定性说明；有同口径数据才绘制定量对照。首批深入完成三个证据充分的场景，其余在资料核验后补充。

### 生产力实验室：交互式瓶颈演示

以“需求整理 → 内容生产 → 人工复核 → 交付”为示例流程。

- 输入：任务量、AI 可参与任务比例、参与任务的加速倍率、额外复核时间。
- 输出：总工时、节省工时、各阶段时间占比；参数变化时图与解释同步更新。
- 视觉表现：基准与 AI 情景展示为上下两条流程轨道，任务粒子按模型时间推进，阶段耗时条与结果同步更新。提供开始、暂停、重播与统一播放倍率；阶段宽度表示时间时注明比例，避免把演示速度误当现实吞吐量。
- 示例公式：原任务工时为 B，AI 参与比例为 a，加速倍率为 s，额外复核工时为 R，则新工时为 `B × ((1-a) + a/s) + R`。多阶段流程按阶段计算后汇总。
- 明确模拟的是串行任务总工时；如果增加并行吞吐量演示，另行定义工作站容量和瓶颈模型，不混用两者。
- 提供基准重置、两种情景并排比较、参数写入 URL，便于分享演示结果。
- 参数使用透明的教学假设，标记“情景模拟”；不推导现实 GDP 或企业收益预测。默认参数及单位实施时确定。

重点表达：局部任务加速不等于整体生产率按同样比例增长；人工复核与其他环节会影响最终收益。

## 4. 数据计划与已找到的来源

以下为已找到的官方报告或研究入口，尚未完成表格提取与逐项核验。实施时固定版本、数据年份及检索日期，并优先核验最新可用版本。

1. 概念定义：[教育部转载的新质生产力论述](https://www.moe.gov.cn/jyb_xwfb/moe_176/202405/t20240531_1133413.html)。用于机制图与概念解释。
2. 投资、采用及劳动市场：[Stanford AI Index 2026 · Economy](https://hai.stanford.edu/ai-index/2026-ai-index-report/economy)。提取口径可比的时间序列；调查中的组织采用率不能写成全部企业的普及率。
3. 工作效率研究：[NBER · Generative AI at Work](https://www.nber.org/papers/w31161)。用于客服场景和技能差异；实施时核对论文版本，不混用工作论文与后续修订的效果数值，不外推为所有行业平均提升。
4. 基础条件与发展差异：[World Bank · Digital Progress and Trends Report 2025](https://www.worldbank.org/en/publication/dptr2025-ai-foundations)。用于人才、基础设施和技术扩散条件。
5. 能源：[IEA · Key Questions on Energy and AI（2026）](https://www.iea.org/reports/key-questions-on-energy-and-ai/executive-summary) 与 [Energy and AI（2025）](https://www.iea.org/reports/energy-and-ai/energy-demand-from-ai)。数据中心用电不能直接标为 AI 用电；历史观测与预测情景分开绘制，版本之间不拼接成同口径实测序列。
6. 中国产业案例：待检索工信部、国家统计局及机构原始材料；确认指标定义、时期和样本后纳入，不预先承诺省级 AI 热力地图或全国统一产业排名。

数据组织：每条指标保留 `id`、名称、值、单位、时期、地区、样本/适用范围、来源 ID、报告版本、图表/页码或章节、统计类型（观测/预测/模拟）、限制说明。来源注册表另存标题、机构、URL、检索日期与使用许可信息。

图表使用本地整理后的 JSON/CSV，页面运行不依赖外部接口。每张图就近显示来源、单位、年份和口径，附可查看的数据表。缺失值展示缺失，不插补为零；不同研究指标不简单平均或拼成排行榜。

## 5. 视觉设计

定位：适合探索和演示的交互式数据专题。

- 延续现有冷灰蓝与深色主题，主色蓝，绿色表示效率改善，橙色提示条件与代价；颜色同时配文字或图形编码。
- 页面采用“一个问题 + 一句结论 + 一张主图 + 二至三个辅助模块”的层级，结论在数据核验后撰写。
- 总览使用占据主要视野的机制网络，配克制的局部光晕和渐变路径；正文滚动时依次展开“数据与算力 → AI 能力 → 产业任务 → 效率、质量、创新”。节点位置以分层锚点约束，便于阅读；提供分步按钮执行相同操作。
- 发展脉络采用可框选时间范围的趋势图，联动地区排名；排名变化使用平滑重排。跨年口径一致且数据足够时增加年份播放，不补造中间年份。
- 人机协作使用哑铃图或效果点图展示同口径对比，选中研究时突出对应证据；仅在原研究提供时显示置信区间。
- 统计图的轴、图例和正文保持清晰，视觉强调集中于关键关系和当前选择。
- 动画服务于机制展开、数据变化与任务流动；尊重减少动态效果设置，支持暂停，页面不可见时停止持续动画。
- 统一图表容器、来源脚注、指标卡与筛选控件；移动端优先重排图表，复杂矩阵可在自身容器内滚动。
- 目标约 10–14 个有独立信息价值的可视化模块，实际数量由资料质量和页面密度决定。

## 6. 技术方案

- 保留 Astro 静态多页架构，新增 `src/homework/hw02/` 存放布局、组件、文案、页面配置和脚本，数据位于 `public/data/hw02/`。
- 使用专属 `Hw02Layout.astro` 包装 `BaseLayout`，页头作业导航始终高亮 HW02，侧栏单独高亮当前子页。
- 使用 D3.js + TypeScript + SVG 实现所有主要图表，CSS 负责界面样式；按需导入 D3 模块，实施时确认依赖版本。只有大量粒子的性能测量确有需要时才使用 Canvas，标签与控件保留在 SVG/HTML。
- D3 分工：`d3-selection` 的数据绑定与 keyed join 管理图形；`d3-scale`、`d3-axis`、`d3-shape` 绘制统计图；`d3-force` 布局产业网络；`d3-drag`、`d3-zoom` 支持探索；`d3-brush` 联动时间筛选；`d3-transition`、`d3-interpolate`、`d3-timer` 驱动数据过渡和流程动画。
- 教学展示：在数据与方法页增加“可视化实现”折叠区，说明数据如何映射到位置、大小、颜色，以及 selection、scale、axis、join、transition、force、brush 的具体应用；代码片段与真实实现对应。
- 普通子页采用 Astro 真实路由。暂不引入第二套路由系统；如后续需要无刷新导航，先验证与现有语言切换及图表生命周期的兼容性。
- 图表与模拟器可使用 Custom Elements，挂载时初始化，卸载时停止 force simulation/timer、打断 transition、清理观察器和事件；主题或语言变更时更新图形。通过 ResizeObserver 响应容器变化，保留选中项并更新比例尺和坐标轴。
- 当前语言切换会替换主内容 DOM，且只按顺序保存部分表单值。HW02 的复杂状态需要稳定键或 URL 状态恢复；保留已有 HW01 行为。
- 所有导航、数据加载和资源链接兼容部署 base；中英文子页结构一致。
- 数据确定、真实入口可用后再注册 `meta.ts` 并设 `ready: true`，避免把草案暴露为完成作业。
